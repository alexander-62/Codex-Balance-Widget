# Phase 01.1: Address Phase 1 tech debt - Context

**Gathered:** 2026-07-21

<domain>
## Phase Boundary

Close 3 unresolved code-review findings from Phase 1 (`01-REVIEW.md`, carried forward into `01-VERIFICATION.md`'s Anti-Patterns section, still open at milestone-audit time per `v1.0-MILESTONE-AUDIT.md`):

1. **CR-01**: `probe_wham_usage.py`'s stdout print path (`main()`) prints the `redact()`ed payload without the same `redaction_clean()` post-check that `write_fixture()` already has. No observed leak today, but no defense-in-depth against an unanticipated future PII-bearing key name.
2. **CR-02**: `collect_windows()` assumes `rate_limit` / `additional_rate_limits[]` entries are dicts once truthy. A non-dict value raises an uncaught `AttributeError` that escapes `main()`'s single `except ProbeError` handler.
3. **WR-01**: `main()` only catches `ProbeError`; any other exception type (including CR-02's `AttributeError`) bypasses the single-diagnostic contract and would surface a raw Python traceback to the user instead of a clean message.

Pure hardening/bug-fix phase — no new user-facing behavior, no new features. Scope is confined to `probe_wham_usage.py` (the standalone Phase 1 probe script) and its test suite. Does not touch `codex_balance_widget_chrome.py` or `json_usage_provider.py` (Phase 2 already has its own equivalent broad-exception handling, added and reviewed separately).

</domain>

<decisions>
## Implementation Decisions

### Claude's Discretion
This is an infrastructure/bug-fix phase (technical fixes only, no user-facing behavior change, no design choices) — discuss was skipped per the smart-discuss infrastructure-detection rule. All implementation choices are at Claude's discretion, guided by:
- The exact fix shape already proven in Phase 2 for the analogous problem: `json_usage_provider.py`'s `_fetch_with_retry` was hardened from catching only `ProbeError` to also catching bare `Exception` (see `02-REVIEW.md` CR-02 / commit `4370c0c`). The same broadening pattern (catch `Exception` at the outermost boundary, convert to the existing clean-diagnostic contract) should be mirrored in `probe_wham_usage.py`'s `main()`.
- `write_fixture()`'s existing `redaction_clean()` post-check is the reference implementation for CR-01 — the stdout print path should gain the same post-check (or share the same helper), not a divergent second scheme.
- CR-02's fix should make `collect_windows()`/`pick_window()` defensively validate window entries are dicts before attribute/key access, or let the resulting `TypeError`/`AttributeError` be caught by WR-01's broadened `except` in `main()` — whichever is more consistent with `probe_wham_usage.py`'s existing error-handling style (prefer explicit validation with a clear `ProbeError` over relying solely on a catch-all, per Phase 1's existing pattern of raising `ProbeError` with Russian diagnostic messages for all other error paths).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `redaction_clean()` in `probe_wham_usage.py` — already implements the exact post-check needed for CR-01; `write_fixture()` shows the call-site pattern to mirror for the stdout path.
- `ProbeError` (with the `retryable` flag added in Phase 2) — the existing exception type `main()` already catches; WR-01's fix should keep using this as the single diagnostic contract, just widen what gets converted into it.
- Phase 2's `json_usage_provider.py` `_fetch_with_retry` (commit `4370c0c`) — direct precedent for "catch bare `Exception` at the boundary, don't let it escape as a raw traceback."

### Established Patterns
- All error paths in `probe_wham_usage.py` raise `ProbeError` with a single Russian-language diagnostic string; `main()` catches exactly that type and prints/exits cleanly. The fix should preserve this one-error-type-one-clean-message contract rather than introducing a second error-handling style.
- Redaction is denylist-based (`redact()`) with an assertion-style post-check (`redaction_clean()`) as a second line of defense — CR-01 fix extends this defense-in-depth pattern to the stdout path instead of inventing a new mechanism.

### Integration Points
- `probe_wham_usage.py main()` is the sole integration point — no other file imports or depends on these three fixes. Phase 2's `json_usage_provider.py` already has its own independent exception handling and does not call `probe_wham_usage.main()`.
